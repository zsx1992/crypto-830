### 5.2.2 回测流程

```
┌─────────────────────────────────────┐
│ ① 样本准备                           │
│  · 从 labels.json 读取每张图的标注     │
│  · 提取: symbol, interval, pattern   │
│  · 用 API 拉取对应时间段的 K 线数据    │
└──────────┬──────────────────────────┘
           │
           ▼
┌─────────────────────────────────────┐
│ ② 运行扫描器                        │
│  · 用当前 config.yaml 跑完整识别流程   │
│  · 记录所有 candidates 和 signals     │
└──────────┬──────────────────────────┘
           │
           ▼
┌─────────────────────────────────────┐
│ ③ 对比评估                          │
│  · 命中(Hit): 标注有 & 扫描器也检出    │
│  · 漏判(Miss): 标注有 & 扫描器没检出   │
│  · 误报(False Alarm): 标注无 & 扫描器 │
│  · 正确拒绝: 标注无 & 扫描器也无       │
└──────────┬──────────────────────────┘
           │
           ▼
┌─────────────────────────────────────┐
│ ④ 计算指标                          │
│  · Precision = Hit / (Hit + FA)      │
│  · Recall = Hit / (Hit + Miss)       │
│  · F1 = 2 × P×R / (P+R)            │
│  · 按形态 / 周期 / 标的 分层统计      │
└─────────────────────────────────────┘
```

### 5.2.3 避免未来函数（Look-ahead Bias）

回测中最容易犯的错误：

| 错误行为 | 为什么错 | 正确做法 |
|---------|---------|---------|
| 用"未来"的 K 线来确认突破 | 实盘不可能知道未来的收盘价 | 只用截至"检测时刻"的数据 |
| 用标注图上的"事后最优"颈线 | 人眼有后视偏差 | 算法必须在突破前就确定好颈线 |
| 用全部历史数据优化参数 | 过拟合 | 用 walk-forward 验证 |
| 只挑成功的案例测试 | 幸存者偏差 | 必须包含失败案例 |

**具体防护措施：**

```pseudo
function backtestSample(sample, klines, detector):
    # sample 中有时间戳信息（从文件名提取的日期）
    detectionTime = parseDateFromFilename(sample.file)

    # 截止到"标注时刻"的数据（不含之后发生的K线）
    cutoffIndex = findBarIndexAtOrBefore(klines, detectionTime)
    availableData = klines[:cutoffIndex + 1]

    # 在这个截止点上运行检测器
    result = detector.detect(
        pivots=findPivots(availableData),
        klines=availableData,
        ...
    )

    # 对比结果
    return {
        "expected": sample.patterns[0],        # 用户标注的形态
        "actual": result.patternType if result else null,
        "match": result is not null and result.patternType in sample.patterns,
        "lookaheadSafe": true                  # 标记已通过防偏差检查
    }
```

### 5.2.4 参数敏感性分析

对每个关键阈值做网格搜索：

```pseudo
function parameterSensitivity(paramName, values, samples):
    results = []
    for val in values:
        cfg = loadBaseConfig()
        setParam(cfg, paramName, val)

        hits = misses = fa = 0
        for s in samples:
            outcome = backtestSample(s, klines[s.symbol], detectors)
            if outcome.match: hits += 1
            elif s.hasPattern and not outcome.actual: misses += 1
            elif outcome.actual and not s.hasPattern: fa += 1

        precision = hits / (hits + fa) if (hits+fa) > 0 else 0
        recall = hits / (hits + misses) if (hits+misses) > 0 else 0
        f1 = 2*precision*recall/(precision+recall) if (precision+recall) > 0 else 0

        results.append({paramName: val, precision, recall, f1})

    return results   # 用于绘制敏感性曲线
```

**重点分析的参数：**

| 参数 | 测试范围 | 步长 | 影响 |
|------|---------|------|------|
| peak_tolerance | 0.01 ~ 0.06 | 0.005 | 双顶/头肩灵敏度 |
| left/right (ZigZag) | 2~8 | 1 | 摆动点密度 → 影响所有形态 |
| breakout_candles | 1~4 | 1 | 确认严格度 |
| breakout_atr_ratio | 0.2~1.0 | 0.1 | 抗毛刺能力 |
| volume_ratio_min | 1.0~3.0 | 0.25 | 量能确认力度 |

### 5.2.5 Walk-Forward 验证

```
时间轴: |----训练区----|--验证区--|--测试区--|
         2023-07~2023-09  2023-10~2023-11  2023-12~

步骤:
1. 用训练区的标注样本调参（找到最佳 F1 的参数组合）
2. 固定参数，在验证区跑回测（不能改任何参数！）
3. 记录验证区的 Precision / Recall / F1
4. 如果验证区 F1 与训练区差距 > 15% → 过拟合信号，回到第 1 步简化模型
5. 通过后在测试区做最终评估（只报告一次，不再调整）
```

你的样本集时间跨度是 **2023-07 到 2026-01**（约 30 个月），足够做 2~3 轮 walk-forward。

# 附录 C：检测器实测验证结果

> 数据来自真实 Binance API + 82 个金标准标注样本回放
> 标定时间：2026-08-30

## C.1 核心结论：一致率远低于预期，必须知道

| 判定标准 | 命中率 | 含义 |
|---------|-------|------|
| 严格命中（形态末端距截图 ≤25 根K线） | **4.9%** | 大概率对应截图里的那个形态 |
| 宽松命中（窗口内任意位置检出） | **18.3%** | 含大量数据别处的偶然匹配 |
| 多尺度「任意类型」命中 | **65.9%** | 该位置检出了某种形态 |

**读法**：系统在 66% 的样本位置能感知到"这里有结构"，
但把它归到和你相同的形态类别，只有 ~5%（严格）到 ~18%（宽松）。

**参考基准**：图表形态识别是公认难题。
研究表明人工标注者之间的一致率本身也只有 50~70%。
所以 5% 的严格一致率确实偏低（说明还有改进空间），
但"规则算法 vs 人眼"存在系统性差异是正常现象，不应期望 90%+。

## C.2 多尺度的效果（已启用）

| 配置 | 精确类型命中率 |
|------|--------------|
| 单尺度 (5,5) | 8.5% |
| **多尺度 [3,5,8,12]** | **15.9%** |
| 多尺度 同族匹配 | 23.2% |
| 多尺度 任意类型 | 65.9% |

**原理**：人眼看图会自动做视觉平滑——放大是小波动，缩小就融进趋势。
固定 left/right 的 ZigZag 只有一种尺度，必然与人的视角错位。
多尺度在不同粗细上各跑一遍再合并，能覆盖更多视角。

代价：计算量 ×4，候选形态变多（需靠去重和过滤收敛）。

## C.3 排除的假设（测过但无效，避免重复踩）

| 假设 | 测试方法 | 结果 |
|------|---------|------|
| 时区错了 | 偏移 0/4/8/12/16/20 小时 | **完全无影响**（各档都 11/30） |
| ZigZag 窗口不合适 | 扫描 (2,2)~(10,10) | **几乎无影响**（7~10% 横盘） |
| 容差太严 | 扫描 0.03~0.15 | 有效但有限（2.4%→15.9%，且误报同步升） |

时区测试还额外验证了一件事：`endTime` 参数确实生效
（LINK 15m 偏移 0 vs 8 小时拿到不同的最后一根 K 线）。

## C.4 调参的收益与代价

| 参数组合 | 严格命中率 | 代价 |
|---------|-----------|------|
| 容差 0.03 / 谷深 0.05（原默认） | 2.4% | 漏掉大量真实形态 |
| 容差 0.08 / 谷深 0.03（当前配置） | 4.9% | 误报增加 |
| 容差 0.12 / 谷深 0.03 | 8.5% | 误报明显增加 |

**当前 config.yaml 采用偏松参数**（`peak_price: 0.08`），
理由是：漏掉机会的成本 > 多看几条消息的成本。

如果你觉得信号太吵，把 `patterns.tolerance.peak_price` 调回 0.05~0.06，
观察一周再定。

## C.5 实盘扫描的信号产出率

| 规模 | 扫描次数 | 新鲜信号数 | 产出率 |
|------|---------|-----------|-------|
| Top40 × 4周期 | 160 | 1 | 0.6% |
| Top60 × 4周期 | 240 | 4 | 1.7% |

## C.6 一个真实信号样例（验证计算链路正确）


## D.1 方法

- walk-forward：对每个标的取 1000 根 4h K线，从第 150 根起每 50 根设检查点

| 止损触发率 | 64.7% | 83.3% |
| 平均盈亏 | **-0.28 R/笔** | **-0.50 R/笔** |
| 期望值 | 负期望 | 负期望 |

按方向：做多胜率 0~36%，做空 25~33%。在近半年行情里，**突破后继续反向的概率高于顺势**。

## D.3 重要说明（别过度解读）

1. **样本太小**：6~17 笔不具备统计意义，至少需要几百笔才能下结论
2. **单一市场状态**：近半年可能属于对突破策略不利的震荡/反转市
3. **单一时间框架**：只测了 4h；15m 假突破更多，1d 信号太少
4. **资金管理固定**：全仓止盈1=1×高度，未做分批止盈/移动止损

## D.4 结论与改进方向

当前参数下**不能证明策略盈利**，但也不能证明亏钱（样本不足）。
最可能的短板（按收益期望排序）：
1. **缺少趋势过滤**：做多信号若大趋势向下，胜率显著下降（本测做多 0~36%）
   → 下一步：严格化 trend_consistency 权重，或直接要求 4h 趋势同向才推
2. **止盈位过于激进**：1×高度可能太高 → 试试 0.5×高度 + 移动止损
3. **入场时机**：突破后回踩入场（现已是）比追突破好，可进一步等回踩确认
4. **扩大样本**：更多标的 + 更长历史（1500+ 根）+ 15m/1d，把 6 笔扩到几百笔再定论

## D.5 趋势过滤实验（2026-08-30 追加）

在 D.1 方法基础上，用 40 标的 × 1500 根 4h K线 做了趋势过滤开/关对照：

| 配置 | 信号数 | 胜率 | 平均盈亏 |
|------|-------|------|---------|
| 趋势过滤开（EMA20/50 同向才推） | 11 | 36.4% | **+0.10 R** |
| 趋势过滤关 | 13 | 38.5% | **+0.16 R** |
| 关 + 无任何强度过滤（早期基线） | 17 | 35.3% | -0.28 R |

**结论：**
1. 趋势过滤开/关差异在噪声范围内（11 vs 13 笔），**不能证明有效**
2. 它只滤掉了 2 个信号——当前周期的 EMA 趋势过滤太弱，几乎没有筛选力
3. 更大样本（40×1500）下总体期望翻正（+0.1~0.16R），但样本仍不足以定性
4. 形态差异明显：double_top(空) 胜率 67~75%、double_bottom(多) 33~40%、
   head_shoulders_top 全亏——**近期行情做空信号强于做多**

**决定：`require_trend_alignment` 默认关闭**（避免基于噪声改变实盘行为）。
要真正验证趋势过滤，需换成【更大周期趋势】（如 4h 信号看 1d 趋势）再测，
且需要几百笔样本，当前 11~17 笔做不到。

## D.6 扩样本盈利回测（2026-09-01，49 标 × 2100 根 4h + 1d 大周期）

### 数据与工具

- **数据源**：Binance 官方历史数据站 `data.binance.vision`（国内可直连，无需梯子），
  49 个 USDT 永续 × 12 个月 4h（2190 根/标的）+ 14 个月 1d（426 根/标的）
- **工具**：新增 `tools/download_binance_klines.py`（批量下载+月度合并去重）；
  `tools/backtest_profitability.py` 新增 `BT_LOCAL_DIR`（本地 CSV 离线回测）
  与 `BT_LOCAL_1D_DIR`（1d 大周期趋势对齐分组）；FRESH_MAX 对齐实盘 config 4h=12
- **方法**：同 D.1 walk-forward（检查点防前视），信号过滤与实盘一致（强度≥60、RR≥1.5）

### 总体结果（33 笔，从 D.5 的 11~17 笔扩到 33 笔）

| 配置 | 信号数 | 胜率 | 期望 R/笔 |
|------|-------|------|----------|
| 止盈 1.0x（现配置，趋势过滤关） | 33 | 30.3% | **-0.09 R** |
| 止盈 0.75x | 33 | 39.4% | **+0.26 R** |
| 止盈 0.5x | 33 | 48.5% | **+0.56 R** |
| （D.5 基线 40标×1500根） | 13 | 38.5% | +0.16 R |

止盈缩放单调改善：**1.0x → 0.75x → 0.5x，期望 -0.09 → +0.26 → +0.56 R**。
原因：形态高度 1 倍的目标经常在触达前先回踩打止损；0.5x 更早落袋，胜率 30%→48.5%。

### 分维度区分度

**按方向（1.0x 止盈）：**

| 方向 | n | 胜率 | 期望 |
|------|---|------|------|
| LONG | 12 | 25% | -0.30 R |
| SHORT | 21 | 33% | +0.03 R |

做多信号明显偏弱（与 D.5"近期行情做空强于做多"一致）；0.5x 止盈下 LONG 翻正（+1.19R，67%胜率）。

**按形态（1.0x 止盈）：**

| 形态 | n | 胜率 | 期望 |
|------|---|------|------|
| head_shoulders_top | 13 | 38% | +0.25 R |
| double_bottom | 10 | 30% | -0.16 R |
| double_top | 8 | 25% | -0.32 R |

注意：D.5 曾说 head_shoulders_top"全亏"，大样本下翻转为 +0.25R——再次印证样本量决定结论可靠性。
0.5x 止盈下 double_bottom 达到 70% 胜率、+1.01R。

**按 1d 大周期趋势对齐（任务②，4h 信号 vs 1d EMA20/50 趋势）：**

| 对齐 | n | 胜率 | 期望 |
|------|---|------|------|
| 同向（顺 1d 趋势） | 22 | 23% | -0.31 R |
| 逆向（逆 1d 趋势） | 11 | 45% | +0.35 R |

**反直觉结果**：逆着 1d 大趋势的 4h 信号反而更好。可能解释：本系统主推的是
反转形态（双顶/双底/头肩顶），逆大势突破 = 强反转信号。但 n=11 vs 22 样本太小，
**不能据此开启任何"逆向过滤"**，只作观察项。结论：`require_trend_alignment` 保持关闭是正确的。

### 结论与实盘建议（待确认）

1. **止盈 1.0x → 0.5x（或 0.6x 折中）**：同一批信号出场更早，期望从负转正，改善显著且逻辑自洽
2. **趋势过滤不开**：1d 同向反而差，且样本小，维持 `require_trend_alignment: false`
3. **做多信号警惕**：LONG 在 1.0x 下 -0.30R，可考虑提高 LONG 的 min_strength（观察项）
4. **分级推送**：按形态历史表现打标（head_shoulders_top 较稳、double_top 最弱）

### 边界（诚实声明）

- 33 笔仍属小样本，-0.09R vs +0.56R 的差异置信区间较宽，需实盘小仓位/挂机继续验证
- 数据源为 Binance 永续（实盘主源 OKX），同市场价格差异小，但严格说非同源
- 覆盖 2025-07~2026-07 单一年份，含特定市场环境（做空偏强的结构性行情）
- 0.5x 改善是"同批信号换出场"的结果，未来行情下胜率/盈亏比可能变化
